# Initial voice validation — 18 October 2026

This is an engineering smoke baseline, **not human-speech accuracy or measured
microphone-to-ear latency**. Six short utterances were generated by Piper: three
English and three Hindi, using the example WER manifest. No human test recordings
were available. The full channel used the actual speech models, the production
customer graph/tools and configured Groq model through an in-process WebSocket,
with fresh fictional identities and in-memory checkpoints.

## Environment and method

- Windows 11, AMD64 Family 23 Model 96 Stepping 1 (AuthenticAMD).
- faster-whisper multilingual small, CPU/int8, two ASR worker threads, beam size five.
- Piper `en_US-lessac-medium` and `hi_IN-pratham-medium`; Silero ONNX VAD.
- 16 kHz mono PCM16 input, real-time frame pacing and continuous silence while waiting.
- ASR WER was measured on the synthesized reference clips before the full-channel run.
- Full-channel input was independently segmented by Silero and transcribed again;
  its ASR times therefore differ from the ASR-only pass.
- Model loading completed before ready. The first policy retrieval still incurred
  cold retrieval/model initialization during the agent stage; that outlier is included.
- Reports use timestamps and preserve earlier unsuccessful runs. A previous smoke
  harness timed out because it stopped sending frames; that run is not hidden or
  merged into the corrected six-turn report.

## Results

All six corrected full-channel turns completed successfully.

| Metric | English (3 clips/turns) | Hindi (3 clips/turns) |
| --- | --- | --- |
| Synthetic-clip corpus WER | 0.00% | 14.29% |
| ASR-only mean latency | 6.41 s | 6.71 s |
| Full-channel mean ASR latency | 5.63 s | 6.78 s |
| Mean first-audio-send latency | 20.13 s | 10.20 s |
| Median first-audio-send latency | 8.43 s | 9.97 s |
| Mean server turn-completion latency | 21.40 s | 11.15 s |
| Median server turn-completion latency | 8.78 s | 9.97 s |

The first English policy turn took **45.02 s to first audio** and **47.56 s to
server completion**, including **38.06 s in the agent stage**. The other two English
first-audio values were 8.43 s and 6.95 s. This is a useful cold-start finding, not
a reason to drop the slow sample from the mean. English/Hindi samples use different
questions, so their full-channel latencies are not a controlled language-only
comparison. Three samples per language are too few for reliable tail estimates.

First-audio/turn timing starts at the last speech-positive input frame received
and includes endpointing silence. It ends at server chunk send/completion, not
physical browser playback. Actual microphone capture, network transit, playback,
echo cancellation and human accents were not part of this run.

Synthetic WER is not representative of real users; generated speech can make a
recognizer appear better than it is. No Marathi/Tamil/Telugu quality score is
claimed. The optional Indic-Parler adapter was not downloaded or validated; its
model requires a separate access/dependency setup.

These files and the generated clips remain ignored local artifacts. Reproduce
after preparing models with:

```powershell
python -m scripts.smoke_voice --live-agent
python -m scripts.evaluate_voice --turns PATH_TO_NEW_SMOKE_REPORT.json
```

This explicitly makes hosted Groq calls. To measure actual human ASR performance,
record consented English/Hindi clips and follow the manifest workflow in
[the voice guide](voice.md). Record hardware, model sizes, warmup protocol,
speaker/noise distribution, completed/failed counts, WER and latency together.
